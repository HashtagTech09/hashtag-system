# Cash Payment with Staff Confirmation Flow

## Overview

When a student selects "Pay by Cash" at the register page, they also select a staff member. A magic link is sent (via email) to that staff member. The staff clicks the link, sees the amount, confirms receipt, and the payment + enrollment is finalized. The payment record stores the confirming staff's ID.

## Database Changes

### 1. Add `confirmed_by_staff_id` to `payments` table

```sql
ALTER TABLE public.payments ADD COLUMN confirmed_by_staff_id bigint;
```

### 2. Create `cash_payment_requests` table

Stores pending cash payment requests awaiting staff confirmation:

```sql
CREATE TABLE public.cash_payment_requests (
  id bigint generated by default as identity primary key,
  organization_id bigint NOT NULL DEFAULT 1,
  student_id bigint NOT NULL,
  staff_user_id bigint NOT NULL,
  token text NOT NULL UNIQUE DEFAULT gen_random_uuid()::text,
  amount numeric NOT NULL,
  gst numeric NOT NULL DEFAULT 0,
  final_amount numeric NOT NULL,
  enrollment_data jsonb NOT NULL,
  batch_ids jsonb NOT NULL,
  status text NOT NULL DEFAULT 'pending',
  created_at timestamptz NOT NULL DEFAULT now(),
  confirmed_at timestamptz
);
ALTER TABLE public.cash_payment_requests ENABLE ROW LEVEL SECURITY;
-- Allow anon read/update for staff confirmation page
CREATE POLICY "Allow anon read cash_payment_requests" ON public.cash_payment_requests FOR SELECT TO anon USING (true);
CREATE POLICY "Allow anon update cash_payment_requests" ON public.cash_payment_requests FOR UPDATE TO anon USING (true);
CREATE POLICY "Allow anon insert cash_payment_requests" ON public.cash_payment_requests FOR INSERT TO anon WITH CHECK (true);
CREATE POLICY "Allow authenticated all cash_payment_requests" ON public.cash_payment_requests FOR ALL TO authenticated USING (true) WITH CHECK (true);
```

## App Changes

### 3. `src/pages/Register.tsx` — Cash payment flow update

In the "pay" step when `paymentMode === "cash"`:

- Add a **staff selector** dropdown (fetches users with staff/admin/frontdesk roles)
- When user clicks "Confirm & Pay", instead of immediately creating payment:
  - Insert a `cash_payment_requests` row with token, enrollment data, amounts
  - Send a WhatsApp message (via existing `send-receipt` or new edge function) to the staff member with a magic link: `{app_url}/confirm-cash?token={token}`
  - Show a "Waiting for staff confirmation" state

### 4. New page: `src/pages/ConfirmCash.tsx`

- Route: `/confirm-cash?token=xxx`
- Reads the `cash_payment_requests` row by token
- Shows: student name, batch details, amount breakdown
- "Confirm Payment Received" button
- On confirm:
  - Creates `payments` row with `payment_mode: "cash"`, `status: "success"`, `confirmed_by_staff_id`
  - Creates `enrollments` and `payment_allocations` from stored `enrollment_data`
  - Updates `cash_payment_requests.status = "confirmed"`
  - Shows success message

### 5. Edge function: `supabase/functions/send-cash-confirmation/index.ts`

- Accepts: `staff_phone`, `staff_name`, `student_name`, `amount`, `confirmation_url`
- Sends Email via resend with the confirmation link as a button
- Logs to `notification_log`

### 6. `src/App.tsx` — Add route

- Add `/confirm-cash` route pointing to `ConfirmCash` page

## User Flow

```text
Student selects batches → Identifies via OTP → Selects "Cash" + picks staff
  → Clicks "Confirm & Pay"
  → Cash request created, Email sent to staff
  → Staff clicks magic link → Sees amount → Confirms
  → Payment + enrollment created with staff ID
  → Student sees confirmation
```
